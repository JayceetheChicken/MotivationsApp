# Sicherheitsrichtlinie

## Sicherheitslücken vertraulich melden

Bitte veröffentliche vermutete Sicherheitslücken, Zugangsdaten oder
personenbezogene Daten nicht in einem öffentlichen Issue.

Bis eine echte Betreiberadresse eingerichtet ist, gilt als deutlich markierter
Platzhalter: **[SECURITY-KONTAKT VOR RELEASE EINFÜGEN]**. Vor einem öffentlichen
Release muss dieser Platzhalter durch einen überwachten vertraulichen Kanal
ersetzt werden, zum Beispiel GitHub Private Vulnerability Reporting und eine
dedizierte Security-E-Mail-Adresse.

Eine Meldung sollte enthalten:

- betroffene Version und Plattform,
- reproduzierbare Schritte mit möglichst wenig personenbezogenen Daten,
- erwartete und beobachtete Auswirkung,
- Hinweise auf bereits erfolgte Offenlegung.

Keine echten Tokens, Passwörter, Service-Role-Keys oder privaten Lerndaten in
die Meldung kopieren. Der Betreiber soll Eingang, erste Risikobewertung,
Behebung und koordinierte Veröffentlichung dokumentieren. Verbindliche
Reaktionszeiten werden erst mit der finalen Betreiberorganisation festgelegt.

## Unterstützte Versionen

Solange Lernzeit noch nicht produktiv veröffentlicht ist, wird ausschließlich
der aktuelle Stand des Standardbranches sicherheitsseitig gepflegt. Diese
Angabe ist mit der ersten produktiven Version zu aktualisieren.
